进程地址空间指的是：

> 每个进程看到的一套独立的虚拟内存地址范围。

程序中使用的指针，例如：

```c
int *p = malloc(sizeof(int));
```

`p`保存的通常不是物理内存地址，而是当前进程的虚拟地址。Linux内核通过页表把虚拟地址映射到实际物理内存。

## 1. 为什么需要虚拟地址空间

假设进程A和进程B都有一个变量，地址都是：

```text
0x7fff12340000
```

这并不表示它们在使用同一块物理内存：

```text
进程A虚拟地址0x7fff12340000 → 物理页A
进程B虚拟地址0x7fff12340000 → 物理页B
```

因此不同进程可以使用相同的虚拟地址，而不会互相覆盖。

虚拟地址空间提供：

* 进程隔离；
* 内存访问保护；
* 统一的地址视图；
* 虚拟内存；
* 文件映射；
* 共享内存；
* 写时复制。

## 2. 典型进程地址空间布局

以64位Linux程序为例，从高地址到低地址通常可以理解为：

| 地址区域    | 主要内容                | 特点         |
| ------- | ------------------- | ---------- |
| 内核空间    | Linux内核和驱动使用        | 用户程序不能直接访问 |
| 栈Stack  | 局部变量、函数参数、返回地址      | 通常向低地址增长   |
| 内存映射区   | 动态库、`mmap()`、共享内存   | 按页映射       |
| 堆Heap   | `malloc/new`动态分配的内存 | 传统上向高地址增长  |
| BSS段    | 未初始化或初始化为0的全局变量     | 启动时自动置零    |
| 数据段Data | 已初始化的全局变量、静态变量      | 可读写        |
| 只读数据段   | 字符串常量、只读常量          | 通常不可写      |
| 代码段Text | 编译后的机器指令            | 通常只读、可执行   |

需要注意：这是便于理解的传统布局。现代Linux启用了ASLR，具体地址会随机化，`malloc`也可能通过`mmap()`分配大块内存。

## 3. 各区域具体是什么

### 代码段

存放CPU执行的机器指令：

```c
void hello()
{
    printf("hello\n");
}
```

`hello()`编译后的机器码位于代码段。

代码段通常具有：

```text
可读
可执行
不可写
```

避免程序意外修改自己的指令。

### 只读数据段

例如：

```c
const char *message = "hello";
```

字符串字面量`"hello"`通常放在只读区域。修改它属于未定义行为：

```c
message[0] = 'H'; // 错误
```

### 数据段

存放已经初始化的全局变量和静态变量：

```c
int global_value = 10;
static int static_value = 20;
```

### BSS段

存放未显式初始化或初始化为0的全局、静态变量：

```c
int global_array[1000];
static int count;
```

BSS不需要在可执行文件中保存大量的零，只需记录：

```text
这个区域启动时分配并清零
```

### 堆

用于动态内存分配：

```c
int *p = malloc(100 * sizeof(int));
```

或者C++：

```cpp
auto p = std::make_unique<int[]>(100);
```

程序需要通过`free()`、`delete`或RAII释放相关资源。

需要注意，现代内存分配器不一定只通过传统的`brk()`扩展堆，大块分配也经常使用`mmap()`。

### 内存映射区

主要存放：

* 动态链接库；
* `mmap()`映射的文件；
* 匿名内存映射；
* 进程间共享内存；
* 大块动态内存；
* 线程栈。

例如：

```text
libc.so
libstdc++.so
动态链接器
```

通常都映射在这个区域。

### 栈

栈主要保存：

* 函数局部变量；
* 函数参数；
* 返回地址；
* 保存的寄存器；
* 部分临时数据。

例如：

```c
void test(void)
{
    int value = 10;
    char buffer[1024];
}
```

`value`和`buffer`通常位于栈中。

函数返回后，对应的栈空间自动失效，不需要手动释放。

栈空间有限，因此不要创建特别大的局部数组：

```c
void test(void)
{
    int array[100000000]; // 可能发生栈溢出
}
```

## 4. 虚拟地址怎样对应物理内存

基本过程是：

```text
程序产生虚拟地址
→ CPU的MMU查询页表
→ 得到物理地址
→ 访问物理内存
```

Linux通常把内存划分成固定大小的页，常见页大小为4KB。

页表记录：

```text
虚拟页 → 物理页
```

例如：

```text
虚拟页0x1000 → 物理页0x83000
虚拟页0x2000 → 物理页0xA7000
```

这些物理页不需要连续，但进程看到的虚拟地址可以是连续的。

## 5. 申请内存不一定立即占用物理内存

执行：

```c
char *p = malloc(1024 * 1024 * 100);
```

并不一定立即分配完整的100MB物理内存。

Linux可能先预留虚拟地址范围，当程序第一次访问某个页面时：

```c
p[0] = 1;
```

CPU发现对应页还没有映射，引发缺页异常。内核再分配物理页并建立映射，这叫按需分页。

缺页异常不一定是程序错误：

* 合法但尚未加载的页面：内核处理后继续运行；
* 访问非法地址：内核向进程发送`SIGSEGV`。

## 6. fork对地址空间做了什么

执行：

```c
pid_t pid = fork();
```

逻辑上，子进程获得父进程地址空间的副本：

```text
父进程：代码、数据、堆、栈
子进程：代码、数据、堆、栈
```

但Linux一般不会立即复制所有物理内存，而是使用写时复制：

```text
刚fork后：
父进程虚拟页 ─┐
               ├→ 同一个物理页，只读
子进程虚拟页 ─┘
```

当父进程或子进程尝试修改时，触发缺页异常，内核再复制该页：

```text
父进程虚拟页 → 原物理页
子进程虚拟页 → 新复制的物理页
```

所以：

```c
int value = 10;
pid_t pid = fork();

if (pid == 0) {
    value = 20;
}
```

子进程修改`value`不会改变父进程的`value`。

## 7. exec对地址空间做了什么

`exec()`不会创建新进程，而是把当前进程的地址空间替换成新程序：

```text
原代码段、数据段、堆、栈
              ↓ exec
新程序的代码段、数据段、堆、栈
```

进程PID通常不变，但运行的程序和地址空间都被替换。

因此：

```text
fork：创建新进程
exec：用新程序替换当前进程内容
```

## 8. 线程和进程的区别

同一个进程中的线程共享：

* 代码段；
* 数据段；
* BSS；
* 堆；
* 内存映射区；
* 打开的文件描述符。

每个线程独立拥有：

* 栈；
* 寄存器；
* 程序计数器；
* 调度状态。

所以多线程访问同一个全局变量时可能发生竞争，而不同进程默认不能直接访问对方的全局变量。

## 9. 共享内存为什么能通信

正常情况下：

```text
进程A虚拟地址 → 物理页A
进程B虚拟地址 → 物理页B
```

共享内存则是：

```text
进程A某个虚拟地址 ─┐
                    ├→ 同一个物理页
进程B某个虚拟地址 ─┘
```

两个进程中的虚拟地址甚至可以不同，只要最终映射到同一组物理页，就可以交换数据。

## 10. 查看实际地址空间

查看当前Shell进程的地址映射：

```bash
cat /proc/$$/maps
```

查看指定进程：

```bash
cat /proc/<PID>/maps
```

也可以使用：

```bash
pmap <PID>
```

输出中的典型权限：

```text
r-xp：可读、可执行，通常是代码段
rw-p：可读、可写，通常是数据或堆
r--p：只读数据
[heap]：堆
[stack]：栈
```

一句话总结：

> 进程地址空间是Linux为每个进程提供的独立虚拟内存视图，代码、数据、堆、栈和动态库都位于其中，再由页表映射到真正的物理内存。
